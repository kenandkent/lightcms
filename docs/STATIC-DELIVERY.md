# 已发布文章导出与 Cloudflare 发布操作

本文对应当前项目的独立内容发布链路。设置中的“Cloudflare 管理”使用 `/cm/static-delivery`；不需要服务器加密密钥。功能是否已在线上生效，应以实际运行版本和 CI 部署结果为准。

## 账号、Worker 与内容入口

- “Cloudflare 管理”默认列出账号，支持搜索；右上角“添加账号”保存名称、Account ID 和 API Token。操作列“详情”打开该账号的 Worker 列表，新增、编辑、删除均在弹窗内完成。检查连接、凭证轮换与启用/停用收纳在账号详情的连接与凭证区域。
- 新 Worker 先保存配置，再从操作列“更多操作”初始化和核实。初始化后脚本名称固定；未发布 Worker 修改公开地址或环境后进入停用状态，重新核实启用。已有页面的地址/环境变更须到“页面维护”预览并部署，避免旧静态页面与新配置不一致。
- 删除账号会事务性移除本地账号、全部 Worker 配置及其凭证；删除 Worker 只移除该本地配置。两者均不调用 Cloudflare 删除 API，远端站点继续运行。历史任务及产物记录仍遵循原保留策略；只释放被移除配置的当前发布引用，不删除文件。有排队、运行、待核实的发布/恢复任务或初始化时拒绝修改、删除。
- 内容模块在“内容管理”下方依次提供“Worker 页面维护”和“静态产物管理”。Worker 维护先选择列表行，在详情弹窗的页面、版本、维护标签中操作。静态产物页提供分页与筛选，详情弹窗展示引用和保护原因，清理预览、确认及中断恢复保留。任务中心和运行状态的入口及功能保持原样。

## 1. 发布现有文章

1. 在“内容管理”找到已有的**已发布文章**，勾选“静态导出选择”列；每次1–100篇。点击“导出／发布到 Cloudflare”。单篇也可以从文章编辑页进入。
2. 无需单独创建静态导出；选择目标后，点击“预览发布”会自动准备静态文件。系统锁定导出提交时已发布的 Publication，不重新渲染当前模板，不带入未发布草稿。成功后仍可下载 ZIP；只有不含独立文件和外部依赖的单页才允许下载单 HTML，否则使用 ZIP。
3. 选择 Cloudflare 账号和 Worker。只有一个可用账号或该账号只有一个 Worker 时自动选择；多个目标仍由用户明确选择，也可使用已校验的 `target_id` 深链接。只列出 enabled 账号的 ready 目标；默认不向忙碌目标并发提交。需要排队时，在可选排队设置中显式勾选“允许非冲突页面排队发布”；同一路径有变化仍会失败并要求重新预览。目标不存在时，管理员先到 Cloudflare 管理页完成初始化与公开地址核验。
4. 审阅报告脚本，确认报告不依赖 CMS 动态接口。勾选脚本/资源确认，再点击“预览发布”，页面自动导出，完成后生成预览；失败时显示原因，不继续发布。静态采集不能证明任意 JavaScript 在脱离 CMS 后仍能工作，不能省略人工确认。
5. 核对账号、Worker、公开地址、增加/替换的路径、保留文章数量和诊断。预览会保存不可变候选站点包，但**不会上传或激活远端版本**；预览有效期一小时。
6. 勾选发布影响确认，点击“确认发布”。系统提交持久化任务，上传完整站点资源、创建未激活版本、记录激活意图、激活版本，再对公开地址进行三轮验证。**只有验证通过后才显示发布成功**。
7. 从发布页的任务进度与访问链接区域复制已验证的分享地址。关闭浏览器不会取消任务；保留带 `job_id` 的操作页地址可以恢复查看。也可以从“Cloudflare 管理 → 报告导出与发布记录”，选择目标，点击最近任务。

仅需下载时，点击“仅准备下载文件（无需 Cloudflare 账号）”。它不要求 Worker 目标或内容发布权限，也不会触发部署；与发布预览复用同一个导出任务。请求结果暂时未知时，当前页面会复用任务/幂等键读取状态，不盲目创建重复任务。

## 2. 关键边界

### 纯静态资源访问（assets-only-v1）

新生成的发布预览会冻结 `delivery_mode=assets-only-v1`。部署只包含 Cloudflare Static Assets，不上传 JavaScript Worker 入口或运行时绑定。健康检查也是静态 JSON；不存在的路径由平台原生返回404，不再执行 JavaScript 兜底。静态资源仍有文件数量、单文件大小等平台限制；这不等于所有 Cloudflare 产品和能力均无限量免费。

文章按公开路径直接上传，MIME 在上传时明确提供，因此无后缀 `/news/a` 和 `/news/a.html` 可以是两篇不同文章；不会用平台默认的HTML后缀归一化把它们合并。首页使用一条静态内部映射，浏览器仍访问 `/`。`/_headers`、`/_redirects` 是平台控制文件名，不能作为新报告路径。

HTML 使用平台默认的每次复验缓存策略，hash资源使用长期 immutable 缓存；测试目标继续禁止索引，版本响应头由平台静态配置提供。部署校验仍核对实际HTML/资源字节、MIME、版本标识和HEAD，平台原生ETag不再被误认成项目SHA-256。

别名 `/article/`、`/article.html` 使用原生308跳转；如果该地址本身是已发布文章，则优先保留真实文章。查询参数保留。包含首页内部映射在内的静态规则超过2000条时，预览明确拒绝，不截断规则。该限制依据 [Cloudflare 静态资源重定向文档](https://developers.cloudflare.com/workers/static-assets/redirects/)。

公开验证分三轮，每批最多四个并发GET/HEAD检查，逐批持久化进度。恢复从固定release的已完成检查点继续，不重新激活，也不从头重复请求全站。只有完成所有检查且再次核实远端归属后，任务才成功。进度页读取经过哈希校验的轻量清单，不反复加载整站文件内容。

当前防御性容量预算：单文件25MiB，导出源HTML与依赖聚合128MiB，发布预览选中的导出源合计128MiB，公开发布包256MiB，私有回滚快照512MiB。超过预算明确失败；它们不是服务器所需内存的承诺。上传桶使用流式multipart/base64，私有快照直接写盘，减少额外整包复制。

升级代码不会自动重发或改写现有Worker。没有该模式字段或使用 `assets-first-v1` 的旧release/已冻结任务继续按旧方式运行；下一次由用户预览、确认的新发布会合并并保留已有文章，切换整个候选站点到纯静态模式，不要求重新创建账号、目标或Worker。已有空占位 Worker 可在核实没有文章和未决任务后，单独迁移并同步归属基线；不能只删掉脚本而不更新管理记录。

- 原 CMS 发布和 Worker 发布是两个独立动作。此操作不修改 `Content.Published`、原 Publication、原 URL、原发布/撤下/回滚流程。原站点撤下不会自动撤下 Worker 副本。
- 同一路径由同一内容更新时替换该页；其他文章保留。不同内容抢占已有路径会被拒绝，不静默覆盖。重命名不会自动删除旧 Worker 路径。
- 导出只接受未删除、非分支、有 verified active（或 API 显式指定的 superseded）Publication 且不可变文件存在的文章。仅有旧 `published=true` 而无可验证快照的历史内容不能冒充已验证产物：先通过原发布/迁移流程获得有效 Publication。
- Worker 的 canonical、OG URL、社交图片和图标在候选 release 中重写；九套报告模板有默认分享图/图标映射。已有动态脚本、外部字体/第三方接口不被伪装为已离线收集。
- 目标必须是本系统初始化的专用 Worker。不接管其他站点、不修改 DNS、不删除远端 Worker，也不使用原 CMS 的 Cloudflare 清缓存凭证。
- `test` 目标使用不索引策略；正式公开发布应选择准备好的 `production` 目标及其正确 HTTPS 地址。

## 3. 异常与重新操作

| 状态/错误 | 操作 |
| --- | --- |
| queued / preparing / uploading / version_ready | 等待；激活意图产生前可点击取消。服务端会再次检查是否允许取消 |
| blocked | 查看错误码并处理账号、权限、目标或资源问题。无激活意图时可取消，重新导出/预览提交新任务 |
| failed / STATIC_JOB_TIMEOUT | 激活前失败自动释放目标。任务从提交起累计上限5分钟，不因重启重置；修正原因后重新预览确认。无需先手动取消失败任务 |
| failed / CF_ACTIVATION_REJECTED | Cloudflare 明确返回非429的4xx拒绝，任务失败并原子释放目标。修正配置或权限后重新预览；网络超时、429和5xx不适用这条释放规则 |
| checkpoint.deadline_exceeded | 已超时但远端激活结果尚未确定，页面明确提示核实中，继续保留目标占用；核实真实成功后可恢复成功，不重复激活 |
| STATIC_REVISION_CONFLICT / STATIC_TARGET_BUSY | 刷新页面，先处理该目标的未决任务，再生成新预览；不要修改旧确认摘要重试 |
| STATIC_ARTIFACT_UNAVAILABLE | 固定产物缺失；恢复私有存储或重新创建导出/预览，不用当前模板偷偷重渲染替代 |
| activation_unknown | 激活结果不确定，后台只读核实，不重复激活、不释放目标，也不能直接取消 |
| active_unverified | 远端可能已上线，但公开地址校验未通过；检查域名、访问策略和资源响应，等待只读恢复，不宣称成功 |
| 页面暂时读取失败 | 点击重新读取任务状态。不要更换幂等键盲目重提 |

幂等键必须在**同一次动作的重试**中复用。同一个键与不同请求体返回409。明确开始新的导出/发布动作应使用新键与新预览。

## 4. 接口与交付范围

机器可读契约：[static-delivery-v1.yaml](openapi/static-delivery-v1.yaml)。REST 前缀 `/api/v1`；后台使用同一服务的 `/cm/static-delivery/api` 会话接口，并附 CSRF。JSON 请求体最多1MiB，未知字段拒绝。

当前实现还提供管理员维护入口 `/cm/static-delivery/maintenance`：撤下路径、单篇/整站回滚、更换公开地址、切换测试/生产环境，以及依据已知上传记录恢复本地与远端版本关系。所有动作要求预览并确认；更换地址必须先在 Cloudflare 绑定同一个专用 Worker，本系统不改 DNS。迁移只在完整公开校验成功后提交目标配置。回滚读取历史固定快照，不使用当前模板重新渲染。

预览默认通过持久化准备任务异步运行，页面刷新可用 `preview_job_id` 继续读取；确认发布仍需重新勾选。网络响应不确定时，同一动作复用幂等键。`queue_mode=merge_nonconflicting` 是显式新协议：只允许保留其他任务修改的无关路径，旧接口默认仍严格检查 `expected_revision`。

`/cm/tasks` 汇总后台任务、静态发布、导入、升级和审批；`/cm/operations` 展示本地队列/对象及容量状态；`/cm/dependencies` 查询当前引用和历史冻结来源；`/cm/artifacts` 仅对新对象存储提供清理预览、显式确认、已开始删除的恢复和人工固定保留。不会自动清理生产数据，也不会轮询抓取 Worker 全站来刷新统计。

新私有包使用内容哈希对象存储，旧 gob 快照继续只读兼容，不自动删除或强制迁移。容量门默认 `STATIC_DELIVERY_MEMORY_BUDGET_MIB=1024`，允许 1024–8192；估算包括解析/复制以及当前、历史或排队重基准所需快照。大包可能需提高该值，否则明确拒绝，不截断内容。此值约束准备任务的预留额度，不是整个 Go 进程 RSS 的硬上限。

操作和恢复文档见 [MODERNIZATION-OPERATIONS.md](MODERNIZATION-OPERATIONS.md)。本地测试通过不代表已经发布到线上，也不代替获授权的真实 Cloudflare 发布验收。

部署和异常恢复见 [STATIC-DELIVERY-RUNBOOK.md](STATIC-DELIVERY-RUNBOOK.md)。本地测试与真实远端验收的区别见[本次 review](reviews/2026-10-20-static-delivery-publish-chain.md)。
