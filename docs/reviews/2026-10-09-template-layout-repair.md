# 九套模板布局修复与验证

日期：2026-10-09。范围：`examples/templates/` 九套自有模板、公开页面渲染、本地及生产模板库。

## 确认的原因与修复

1. 完整模板HTML被再次套入系统主题，响应出现两个doctype/head/main。主题的`.hero`固定高度与渐变、`.sidebar`样式污染报告。完整文档改为直接输出；片段仍沿用原主题。已有标题及JSON-LD不覆盖，缺失时补齐兼容元信息。Fork预览工具栏插入原body内。
2. 九套模板分别调整配色、桌面/手机边距、简介/署名间距、正文标题层级、目录编号与侧栏内边距。去掉正文首段自动首字放大，避免日期被误处理。宽表格与代码局部滚动，不撑开页面。
3. 加密模板现有正文以Markdown传入富文本字段，产生可见标记。仅对该slug的body中包含Markdown标题且不含HTML标签的文档进行兼容渲染；保留字段定义和文章原始data。渲染器版本更新为v2。
4. 九套模板内嵌冻结发布值的Article JSON-LD，保留社交分享元数据、500ms加载、当前英文默认策略以及全部字段。
5. 发布对象原来位于生产容器临时层。增加独立持久卷，并在首次迁移时停止旧容器后复制，支持已停止容器；复制失败阻止替换并尝试恢复原服务，防止漏掉并发写入或停机容器中的对象。

## 验证与证据

- 单文档/片段/缺失SEO/Fork预览回归测试：先观察失败，修复后通过。
- 加密Markdown兼容测试：先观察标题/表格原样显示失败，修复后通过；已有HTML及其他模板富文本不变。
- 全项目测试使用独立测试Mongo，不在开发库执行测试清理。完整日志位于忽略目录`bin/template-repair-20261009`及`bin/template-repair-tests-final-20261009.log`。
- 40项模板语言、500ms延迟、无JavaScript及布局检查。
- 实际文章9套×4宽度（1440/768/390/320）检查：边距、横向溢出、署名与正文重叠、标题对比度、打印文字对比度、超长标题/表格/代码及浏览器异常。截图及结果存于`bin/template-repair-20261009/{local,production}-after/`。
- 停止状态Docker测试容器的发布归档迁移完成字节一致性检查。
- 独立只读代码复核发现并修正两项迁移数据丢失风险及深色模板打印问题。

## 更新与恢复方式

模板更新通过API仅提交html_layout，不替换名称/描述/字段；现有文章逐个显式Publish。保持ID、路径、正文data不变，保留旧Publication用于历史恢复。发布前备份本地及生产数据库、内容目录和模板/文章清单至忽略目录`bin/template-repair-20261009/`，备份不提交仓库。

源代码通过现有main发布流水线部署。生产必须核对新镜像、健康状态及`/app/content/publications`挂载后才更新模板。生产完成记录以该目录的`production.result.json`、实际页面检查结果及流水线成功状态为准；本文件不代替这些运行证据。

社交平台缓存和客户端自己的卡片展示不由模板直接控制；PROD-001仍需按实际平台验证，不能以布局测试代替。
