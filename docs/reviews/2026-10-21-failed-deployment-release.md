# 激活前失败自动释放发布目标

本次范围按用户最新要求聚焦：发布失败自动释放，不再要求人工取消失败任务。
这不是解除同一 Worker 的最终部署互斥，也不引入自动重试或覆盖旧确认快照。
不同 Worker 仍按现有全局并发和账号并发限制运行。

## 行为

- queued / preparing / uploading / version_ready 的执行失败，且数据库中没有
  activation_intent_at：事务内将任务置为 failed、保留 error_code，并按任务 ID
  条件清除该任务持有的 active_job_id。不会清除其他任务的占用。
- 任务状态、执行租约拥有者和激活意图都通过数据库条件确认；旧执行者不能
  覆盖接管者的状态。任务失败和占用释放不能部分提交。
- 已有激活意图时保留现有恢复流程，activating 转 activation_unknown；不允许
  用失败释放来绕过不确定性。active_unverified 也不会被清理。
- 兼容历史：runner 每轮检查 kind=deploy、blocked、无激活意图、租约过期的
  旧任务，将其失败并释放；活跃租约和有激活意图的任务保持不变。
- 账号停用、目标 drifted 等其他限制不因释放而取消。独立静态导出任务的超时
  行为保持不变，它不占用 Worker。
- 不自动再次上传或激活；失败任务保留历史，用户重新预览并确认后提交新任务。
  页面若已缓存旧 busy 状态，需要刷新重新读取目标。

## 验证

数据库回归覆盖：自身目标释放、其他任务目标不被释放、失败后下一任务可取得目标、
有激活意图仍持有目标、旧阻塞任务自动恢复、活跃租约与激活不确定性不被清理。
新规则的回归测试先在旧实现观察到 failed 预期失败，旧实现实际仍为 blocked。

## 五分钟任务上限与自动导出

- 发布任务从持久化 created_at 起累计最多五分钟，包含排队、准备、上传和验证；
  重新获取租约或重启不重置时间。旧配置超过五分钟时向下限制为五分钟；允许
  管理员配置更短上限。预览前自动导出是独立任务，同样受自身五分钟预算限制。
- 超时且尚无激活意图：failed / STATIC_JOB_TIMEOUT，事务释放目标。
- 激活结果尚不确定时：保留恢复状态与所有权，持久化 deadline_exceeded，
  页面显示“已超时，远端结果待核实”。后续仅核实，不重复激活。确认真实成功后
  可以恢复为 succeeded；绝不谎报失败并提前释放可能仍在激活的目标。
- 移除发布页手动导出按钮。选择目标并确认独立性后，点击预览自动创建导出，
  等待导出成功再请求 deployment-preview。导出失败不创建预览、不发起部署。
- 自动导出期间禁用账号/目标切换和重复点击；显示阶段反馈。每个请求最多等待
  30秒。保留导出成功后的下载链接，以及独立导出 API。
- 任务终止后重新读取目标占用和版本，避免页面继续使用旧 busy 状态。
- 前端测试运行实际渲染脚本，覆盖自动导出→预览顺序、重复点击、导出失败。

本轮界面调整遵循 refactoring-ui 的状态反馈原则：保留单一主操作，等待与失败
均显示明确文案，不进行无关视觉改版。
