# LightCMS 全项目功能审查与二开兼容性复核

日期：2026-10-22（Asia/Shanghai）

审查基线：`a2eba093e9c045f4e1754488750439b94550a6cb`，main。

性质：review-only。本次不修改业务实现、不发布新版本、不修改线上内容、账号、Worker 或域名。

## 结论与范围

发现 **11 项问题：3 项 P1、8 项 P2**。其中 6 项已通过本地隔离复现确认，其他项由实际调用链、配置和状态转换直接确认。需要先处理模板引用保护、升级任务重新发布已撤下内容、Cloudflare 明确激活失败仍长期占锁这三项，再完善发布页面及恢复行为。

这次覆盖项目主要功能域及其入口和相互影响，重点深查后续二开功能，不等同于每个业务组合均经过真实线上端到端操作。没有用线上发布/删除操作来验证缺陷。

## P1：优先修复

### F01 后台可以删除仍被文章引用的模板

- **位置**：`internal/handlers/handlers.go:766`、`:773`；对照 `internal/services/template.go` 的 `DeleteTemplate`。
- **触发**：管理员在模板后台删除自定义模板，而该模板仍被已有文章使用。用户当前自建的报告模板不是系统模板，属于此范围。
- **原因**：后台只检查 `IsSystem` 后直接删除数据库记录，没有调用服务层“文章引用数量大于 0 则拒绝”的校验。API 和后台行为不一致。
- **影响**：文章保留一个失效的 `template_id`，后续编辑、模板信息读取、生成/升级可能失败。已有静态页面可能暂时还能访问，不能据此判断删除安全。
- **证据**：本地构造一条已发布文章引用模板，调用真实 `Handler.DeleteTemplate`，返回 303，模板记录确实被删除。
- **修复建议**：后台统一调用模板服务；对在用模板返回明确冲突。若要支持迁移后删除，先显式迁移引用，再删除，不做隐式级联删除。
- **回归要求**：后台/API 均拒绝删除在用模板；无引用模板仍可删除；系统模板仍受保护；历史版本读取不回退到可变数据。

### F02 模板升级任务会重新发布任务创建后已撤下的文章

- **位置**：`internal/product/generation/upgrade.go:284`—`:290`。
- **触发**：文章在模板 v1 上已发布；模板更新到 v2，创建升级任务；随后文章被撤下；再运行旧升级任务。
- **原因**：任务执行时重新取得 active Publication；当已经没有 active 时，`expected` 保持 nil，仍调用 `publishUpgradeItem`。没有将“创建任务时有 active，现在已经撤下”识别为冲突或跳过。
- **影响**：批量升级覆盖了编辑者后来的撤下决定，文章意外重新上线。同类保护还应覆盖任务创建后换模板、变更发布版本等情况。
- **证据**：使用真实 generation/Publication 服务和 MongoDB 复现，撤下成功后运行任务，生成新的 active Publication，任务返回 completed。
- **修复建议**：升级项冻结预览时的 active Publication ID、模板归属等前提；执行时 CAS 核对。已撤下/换模板/发布版本变化的项目进入明确跳过或冲突状态，由用户重新预览，不自动恢复上线。
- **回归要求**：撤下、换模板、并发重新发布、正常升级、失败后重试、断点恢复均覆盖；保持既有幂等和每页发布原子性。

### F03 Cloudflare 明确拒绝激活后仍永久占用发布目标

- **位置**：`internal/product/staticdelivery/runner.go:380`—`:384`；`activation.go:79`—`:95`；取消保护在 `CancelJob`。
- **触发**：版本上传完成，但 activation API 返回明确的 HTTP 400 等拒绝响应。
- **原因**：HTTP 客户端已将这类响应标记为 `Uncertain=false`，Runner 却把所有激活错误统一设为 `CF_ACTIVATION_UNKNOWN`。恢复只观察旧版本，不会将明确未激活的任务终结；激活意图又使取消被拒绝。
- **影响**：超过五分钟仍持续占锁，同一 Worker 后续发布被阻塞；用户修正问题后也不能从正常页面继续发布。不同 Worker 的任务不因此必然被锁住。
- **证据**：隔离测试让远端边界返回 HTTP 400、`Uncertain=false`，把任务年龄推进至十分钟前，再执行恢复：任务仍 activation_unknown，目标仍归该任务，取消被拒绝。
- **修复建议**：持久化“明确拒绝”和“不确定结果”的不同结论；仅明确未激活的任务原子失败并释放自身占用。网络超时、连接断开、服务端不确定响应继续采用现有只读恢复，不能一律按五分钟强行解锁。
- **回归要求**：400/401/403 确定拒绝、超时但远端实际成功、超时仍未完成、重复点击、并发恢复与取消分别测试。

## P2：功能完整性与兼容性

### F04 超时恢复固定 30 秒，但每次从头串行校验整个站点

- **位置**：`internal/product/staticdelivery/runner.go:105`—`:110`；`verify.go:48`—`:73`；`activation.go:108`。
- **触发**：站点文件较多或公网较慢，首次任务达到五分钟；之后进入恢复。
- **原因**：恢复上下文只有 30 秒；校验器每次从第一项开始，对全部文件连续做三轮 GET、对每个页面再 HEAD，并额外等待两次两秒，没有检查点。
- **影响**：即使远端已经完全正确，只要完整校验耗时大于 30 秒，每轮恢复都不能完成，长期 active_unverified 并占用目标。它也会反复产生公网请求。例如 100 个纯页面，单次网络往返平均 100ms，600 次页面请求已约 60 秒，尚未计入其他资源和等待。
- **证据类型**：代码路径确认和请求数量计算；未对生产发起负载测试。
- **修复建议**：有界并发、持久化校验进度/分轮检查点，或使用与总校验工作量匹配的恢复预算；校验进度必须绑定不可变 release/version。保留实际字节、MIME、身份校验，不用 HTTP 200 替代完整性证明。

### F05 独立静态导出在新页面上被 Cloudflare 配置阻断

- **位置**：`internal/handlers/admin_static_publish_templates.go:12`、`:14`、`:30`、`:56`。
- **触发**：只想下载 HTML/ZIP、不准备 Cloudflare 账号；或用户有内容查看/导出权限但没有发布权限。
- **原因**：删除独立导出按钮后，`ensureExport()` 只由“预览发布”触发，而预览必须有 ready 目标；`.CanPublish=false` 时连预览按钮都不存在。
- **影响**：后端支持独立导出，页面却无法使用；“可以导出，但不能部署”的提示与可操作功能不符。
- **修复建议**：保留“一键预览自动导出”的主流程，同时提供不依赖账号/目标的“下载静态页面”操作，并复用同一个导出任务。无需恢复发布流程里的强制手动前置步骤。
- **回归要求**：无 Cloudflare 账号、没有 ready 目标、只读可导出用户、普通发布用户四种状态分别检查。

### F06 完成一次发布后，再次预览的确认按钮仍被禁用

- **位置**：`internal/handlers/admin_static_publish_templates.go:51`、`:56`—`:57`。
- **触发**：在同一个操作页完成一次发布，再选目标或重新生成预览。
- **原因**：首次确认设置 `deploy-start.disabled=true`；只有提交异常的 catch 恢复按钮，新预览生成成功和任务终态都没有恢复。
- **影响**：下一次预览可以正常显示，但用户无法点击确认，需要刷新页面才能继续。失败任务已释放目标时，也可能出现类似“后台已恢复，页面仍不能操作”的情况。
- **证据**：直接执行实际页面脚本，模拟完整“导出→预览→确认→成功→再次预览”，确认面板显示但按钮仍 disabled。
- **修复建议**：以请求/任务状态管理按钮；新预览成功后恢复可确认状态，提交期间防重复，终态刷新目标。不能在仍有未决任务时直接启用提交。

### F07 模板升级任务返回状态和持久化状态不一致

- **位置**：`internal/product/generation/upgrade.go:315`—`:334`。
- **触发**：模板没有文章，或全部文章已经是目标版本而全部 skipped；也包括任务结果写入失败。
- **原因**：只有 `changed=true` 才持久化状态，而零待处理项不会设置 changed；有变化时，`UpdateOne` 的错误也被丢弃。
- **影响**：接口返回 completed，但重新查询任务仍 running；写入失败时还可能报告成功却没有可靠的逐项记录。
- **证据**：空模板创建升级任务后运行，返回 completed，数据库仍为 running。
- **修复建议**：状态有变化即持久化，检查写入结果；对并发执行增加任务版本/租约或 CAS，避免整份 items 相互覆盖。

### F08 纯静态模式丢失既有文章别名跳转

- **位置**：`internal/product/staticdelivery/worker_bundle.go:28`、`:57`；`assets_first.go:77`—`:85`；`cloudflare/assets_only.go:38`—`:47`。
- **触发**：站点存在 `/news/a`，访问旧系统支持的 `/news/a/` 或 `/news/a.html`，且这些地址不是独立的正式文章路径。
- **原因**：别名仍生成在 `routes.json`，但纯静态上传不发送/执行该路由文件；原生 `_redirects` 只包含首页映射。`html_handling=none` 不会替代这些跳转。
- **影响**：旧分享链接/引用链接从 308 变为 404；正式 canonical 地址本身正常。
- **证据**：Cloudflare Miniflare 本地原生资源路由实测：`/news/a`→200，`/news/a/`→404，`/news/a.html`→404。现有旧 Worker 测试仍期望别名返回 308。
- **修复建议**：把不冲突的别名写成原生重定向配置，保持纯静态；明确处理独立 `.html` 文章优先级、query 保留、规则数量上限。不要恢复 JavaScript 404 兜底。

### F09 查询任务进度会反复读取并校验整个发布包

- **位置**：`internal/product/staticdelivery/httpapi/handler.go:253`；`command_queries.go:87`—`:100`；`release_store.go:184`—`:208`。
- **触发**：浏览器保持发布进度页面打开；前端约每 2.5 秒查询一次任务。
- **原因**：每个非导出任务的状态查询都调用 `JobLinks`，后者使用完整 `Store.Load`：读取最大 512MiB 的 gob 快照、解码全部内容、验证清单，再读取所有公开文件做哈希。
- **影响**：本来只需状态/链接的请求反复消耗磁盘、CPU、内存；多窗口或较大站点会影响 CMS 主服务及正在进行的发布。此处是本地磁盘读取，不是每次状态轮询都访问 Worker 网页。
- **证据类型**：调用链确认；未对生产施加压力。
- **修复建议**：任务状态使用轻量记录；链接在成功后读取只含路径的已校验索引或缓存。实际部署核验继续使用完整不可变产物，不能因优化状态接口而削弱校验。

## P2：测试门禁

### F10 CI 的“全量测试”没有强制执行新增发布数据库集成测试

- **位置**：`.github/workflows/deploy.yml:107`—`:115`；`internal/product/staticdelivery/repository_test.go:19`—`:24`；相同条件见 `cmd/server/static_delivery_content_runtime_test.go`、静态发布 HTTP 测试。
- **原因**：CI 只设置 `MONGODB_URI`；新增测试读取 `STATIC_DELIVERY_TEST_MONGODB_URI`，缺失时 Skip，除非同时要求 `STATIC_DELIVERY_REQUIRE_MONGO=1`。
- **影响**：CI 绿色并不能证明新增发布任务、目标锁、数据库事务和 HTTP 集成已跑过。原生 assets 测试也没有作为 CI 新模式验收项；现有 native fixture 显式保留旧 assets-first 模式。
- **修复建议**：在同一个已启动的隔离 Mongo 副本集上设置所需变量，并强制缺失即失败；补入 assets-only 原生路由验收，包括 health、未知路径、首页、别名、MIME 和缓存。
- **本次处理**：本地全量验证显式启用了这两个变量，因此本次新增发布数据库测试没有静默跳过。

### F11 本地测试配置覆盖显式环境变量，破坏隔离

- **位置**：`internal/testutil/testutil.go:48`—`:51`；`internal/handlers/testhelper_test.go:98`—`:101`。
- **原因**：测试 helper 读取 `.env.test` 后无条件 `os.Setenv`，覆盖命令行指定的 URI 和 DATABASE_NAME。多次验证即便指定不同库，也可能落到同一库；每个用例开始还会清空集合。
- **影响**：并行测试会相互清数据，产生间歇性失败，降低 review/CI 结论可信度。不能将这类失败直接当作线上服务故障。
- **本次观察**：初次全量验证与定向复现并行时，`TestUserService_ResetPassword` 在 `user_test.go:337` 对 nil 结果解引用；helper 覆盖隔离配置使并行数据库操作互相干扰。该测试独立执行 10 次通过，services 整包顺序执行通过。
- **修复建议**：显式环境变量优先；仅对未设置项加载 `.env.test`；每个测试运行分配唯一数据库并核实库名，避免不同进程共用清理目标。测试中的数据库读写错误也应明确断言，不忽略后继续解引用。

## 优化项和已知交付边界（不冒充新缺陷）

1. **私有导出/预览包清理**：每次预览保存完整不可变 release；目前没有引用保护的自动 GC，运维文档已明确承认这一限制。应增加磁盘用量、孤立/过期预览统计和可审阅的清理计划，再实施引用保护回收，不能简单按时间删目录。配置中的 90 天/7 天私有包保留参数不表示清理已执行。另一个“退出当前页面的 hash 资源保留 7 天”是设计明确规定，本轮不将它误报为默认 90 天参数错误。
2. **发布目标可维护性**：已有目标变更公开域名、环境、漂移恢复和远端撤下/回滚缺少完整后台操作入口；现有操作文档将它们列为未交付范围。需要单独补齐带预览/确认的流程，不直接改目标记录或复用旧确认摘要。
3. **大文件与批量容量**：导出依赖收集、完整 release 内存快照、multipart 桶上传存在内存放大。当前公开包 256MiB/私有快照 512MiB 上限不能等同于小内存服务器可轻松处理；建议流式上传、早期聚合预算和并发压力验收。
4. **版本化内容与界面说明**：模板/片段编辑不自动改写既有发布内容是当前设计的正确边界。可补足显式“影响哪些文章、需要重新发布”的提示，而不是恢复自动改写线上页面。
5. **项目文档陈旧内容**：`CLAUDE.md` 仍引用不存在的 `VIBECTL.md`，并描述旧 Fly.io 部署、旧目录层级及模板修改自动重生成等流程，与当前项目有偏差。应以当前生产部署/Publication/静态发布文档为准，后续统一文档。
