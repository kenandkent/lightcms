# 兼容性重构：操作与恢复

日期：2026-10-23。本文说明本地代码中的新增能力，不是生产部署确认。原 CMS 运行方式、原站点 Publication、现有 API/MCP/CLI 和纯静态 Worker 访问方式保持不变。

## 后台入口

| 入口 | 用途与边界 |
| --- | --- |
| `/cm/tasks` | 按后台执行、静态交付、导入、模板升级、审批分类。每页 50 条；后台任务详情最多 100 项/100 个事件，只投影摘要，不回传原始上传和凭证 |
| `/cm/operations` | 本地队列状态、最老等待、对象登记数量/大小、Go 内存及准备配额。无公开 Worker 网页轮询；deleted 墓碑的登记大小不是磁盘占用 |
| `/cm/dependencies` | 模板 ID、片段名称、素材路径查询当前内容引用；内容 ID 查询 Publication 已有的冻结依赖摘要，每次最多 50 条。旧记录只有哈希时保持哈希，不反推历史依赖 |
| `/cm/static-delivery/maintenance` | 显式预览/确认撤下、回滚、地址/环境迁移；有证据的版本记录恢复。不会改 DNS 或接管其他站点 |
| `/cm/artifacts` | 新对象存储清理预览、确认、恢复已开始的删除；手动固定/解除固定。不会清理旧 gob、文章、模板或远端 Worker |

内容列表区分草稿版本、原站点发布版本和 Worker 版本/链接；旧记录未知时明确显示未知。Worker 状态只接受与目标当前 release 一致的索引行，索引延迟不会把旧 release 冒充当前。

## 任务、重试与取消

- 导入和合并的草稿写入与逐项检查点处于同一事务。已完成项重启不重复增加版本；取消不撤销已提交项。
- 自动发布和模板升级通过现有 Publication saga，使用固定版本与幂等身份。不确定的外部结果仍需核实，不盲目重发。
- 普通 Webhook 采用至少一次投递；稳定 `event_id` 和 HMAC 供接收端去重。默认最多三次，失败后保留任务，不保证第三方恰好一次收到。
- 后台准备/恢复与静态发布的五分钟截止时间都从提交起算，不因进程重启重置。普通导入/合并/升级内核任务默认 24 小时；各业务内部仍保留原有安全租约和超时。
- 已知激活前失败自动释放目标；未知激活不释放，不因超时谎报“远端未发布”。严格发布仍默认禁止同目标并行激活；选择非冲突排队后只串行合并无关路径。
- 预览和确认的网络重试复用原幂等键；明确修正输入并重新预览才是新动作。刷新 `preview_job_id`/`job_id` 页面只读取，不自动重新提交。
- 多个本地服务进程同时写一个站点仍被原单实例门禁拒绝。任务内核支持租约接管，但本轮不承诺部署为多副本站点写服务。
- 冻结输入采用有界提交：一次任务最多 10000 项、输入合计 8MiB；导入单项最多 1MiB。超过预算明确拒绝，应拆分提交，不静默截断。任务队列默认每类最多 256 个非终态任务。

## 存储与容量

新 release 由 SHA-256 对象和校验清单组成，导出私有来源复用对象；旧 gob 仍有原 reader，不自动改写旧包。发布、回滚、预览都校验固定来源，缺失时报错，不以当前模板重渲染替代。

`STATIC_DELIVERY_MEMORY_BUDGET_MIB` 默认 1024，范围 1024–8192。该额度控制重型准备工作的并发预留，包含快照、解析/复制估算；不是整个进程 RSS 硬限制。大包预留超过额度会明确拒绝。运维应给进程、索引、数据库驱动和系统留额外余量，不能把该额度等同容器全部可用内存。

对象一般保留期使用 `STATIC_DELIVERY_RETENTION_DAYS`（默认 90），失败对象使用 `STATIC_DELIVERY_FAILED_RETENTION_DAYS`（默认 7）。当前 release、未决任务、有效预览、历史保留引用、人工 pin 受保护。清理每批最多 100 个，确认摘要归属当前管理员，有效 15 分钟；删除前再次检查引用/代次并标记 deleting。中断后只接续原计划已开始的删除，尚未开始项需新预览。解除 pin 不等于立刻删除。没有自动生产 GC。

依赖索引在后台构建完整代次，正常约每 5 分钟刷新，读取发现陈旧时请求合并刷新；界面展示时间。素材路径匹配是保守清单，可能多报，不是安全删除或发布授权。Publication 的历史依赖只复制其已有冻结元数据。

## 历史版本缺口只读检查

```sh
go run ./cmd/audit-content -database lightcms
```

读取已有配置中的数据库连接；每页最多 100 篇。返回 `next` 非零时带 `-after <next>` 继续。`HISTORY_GAP` 是缺失范围，`LEGACY_VERSION_UNKNOWN` 是无法确认的旧版本，`HISTORY_SCAN_LIMIT` 表示单篇超过 10000 条需进一步分段核查。它不修改数据库、不生成虚构历史、不重新发布。

## 离线备份与隔离恢复演练

这是新增的显式命令，不改变当前部署脚本。必须先停止 CMS 写进程；备份命令会占用相同站点写入槽并拒绝活跃写入者。备份最长 8 分钟，完成前校验写入权仍有效；超时/失败的目录不能视为完成备份，也不会覆盖已有目录。

示例（路径必须按实际项目配置调整，所有源和目标都在项目内）：

```sh
go run ./cmd/backup -mode create -project . -database lightcms \
  -backup var/backups/point-20261023 \
  -roots content,var/static-delivery,uploads,config.json
go run ./cmd/backup -mode verify -project . -backup var/backups/point-20261023
go run ./cmd/backup -mode restore-test -project . \
  -backup var/backups/point-20261023 \
  -restore-database lightcms-restore-test \
  -restore-files var/restore-drill/point-20261023
```

`-roots` 必须明确列出真实的公开产物、私有清单/对象、上传文件及必要配置；示例不是自动路径发现。不存在的源会失败。备份目录不能包含在任一源中；凭证不会打印，但配置文件和数据库备份可能包含 Token，应按敏感备份保存。

备份包含 Mongo 一致性快照、集合/index 定义及逐文件 SHA-256，完整标记只在成功时写出。站点离线写入槽也阻止 GC 在备份中删除对象，备份自身包含独立文件副本，不依赖未来在线对象保留。

恢复仅接受全新 `*-restore-test` 数据库和新目录；不会覆盖现有库/目录，不启用 TTL 删除，不启动导入、定时发布、Webhook 或 Cloudflare 执行器。文件输出与备份清单均验证哈希。演练通过不代表已恢复生产；生产恢复仍是单独的有授权操作，不能只回滚镜像。

## 健康与验收

- `/livez` 只判断进程可响应。
- `/readyz` 判断核心 Mongo 可用；可选静态交付失效不会让 CMS 整体不就绪。
- `/healthz` 保留原响应协议，可选静态交付配置不可用显示 degraded/HTTP 200，不抓取 Cloudflare 页面。
- 本轮验收使用本地隔离 Mongo、模拟远端协议、原生 Static Assets 协议测试、Node 页面流程和构建；未对生产执行发布、回滚、域名迁移、GC 或数据恢复。
- 按用户要求不在本机打开报告，未执行报告浏览器截图验收。九套模板使用现有结构/语言/响应式契约测试，不将这些测试冒充实际浏览器视觉验收。
