# Cloudflare 管理与静态内容管理交互重构

## 用户要求

- 设置模块保留“Cloudflare 管理”，账号表格右上角添加账号；操作列提供详情、删除。
- 账号详情弹窗展示且只管理该账号下的 Worker，提供新增、编辑、删除。
- 用户已确认删除只移除本系统配置，保留 Cloudflare 上的 Worker 与公开站点。
- 内容模块依次为内容管理、Worker 页面维护、静态产物管理；后两页采用列表、操作列和详情弹窗。
- 任务中心、运行状态的菜单与页面保持原样。
- 从内容列表选择文章后的发布页减少重复选择：唯一账号/Worker 自动选中，保留多个目标选择与显式脚本/发布确认；自动导出、预览、进度和错误在紧凑流程中展示。
- 保留现有发布、预览、确认、回滚、恢复、任务进度与产物引用保护；不在本机打开内容页。

## 实现约定

沿用 Go 服务、MongoDB、服务端 html/template、现有后台 CSS 变量及会话 CSRF。
保留原 URL；列表/表单支持中文与英文，弹窗支持键盘关闭、焦点恢复和窄屏滚动。

账号删除事务性移除本地账号、其 Worker 配置及凭证版本，保留历史发布记录与私有产物，
由既有保留策略管理历史产物。不调用任何 Cloudflare 删除 API。
有正在排队、执行或待核实的发布/恢复任务时拒绝删除或编辑关联配置。
创建 Worker 与删除账号、提交任务与删除 Worker 使用同一记录写入栅栏，避免孤立配置/任务。

编辑 Worker 可以修改显示名称。尚未初始化的 Worker 可改脚本名称、环境与公开地址；
初始化后固定脚本名称。未发布页面的 Worker 修改地址/环境后需重新核实启用。
已有发布的 Worker 的地址/环境变更继续使用维护页预览、确认、部署和公开校验，
不直接覆盖本地配置以制造旧 HTML 与新地址不一致。编辑同时校验部署配置版本和管理编辑版本；
只改显示名称时仅增加管理版本，不改变不可变 release 对应的部署配置版本或恢复能力。

Cloudflare 管理保留检查连接、Token 轮换、启用/停用、初始化与核实操作，收纳在账号/Worker 详情中。
菜单调整只移动两个入口并重命名一个入口，不移除既有服务端路由。
Worker 维护支持按目标深链接，操作弹窗按目标隔离异步结果与确认状态。
保留只有 `recovery_job_id` 的旧恢复入口，由经过授权的任务状态取得目标再恢复弹窗。
静态产物默认有界列表，不读取文件正文；保护原因、引用、固定保留与清理在详情/操作弹窗展示。

## 验证

先写本地删除、账号隔离、配置版本与忙碌保护的失败测试再实现。
验证菜单次序、任务中心/运行状态保留、表格弹窗结构、CSRF、转义和渲染后的 JavaScript。
只使用本地独立 MongoDB 测试库、合成 DOM/静态夹具；完成后运行全量 Go 测试、build、vet。
用户已授权全部完成且按 CI 检查通过后提交、推送 main 并核实 Actions 与线上运行版本。
代码部署不修改生产账号、Worker、域名或内容产物；不在本机打开内容页面。
